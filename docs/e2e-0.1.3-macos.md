# 端到端验证：中断后自动续跑（macOS）

> 2026-09-25，由 DSH（瑠璃）在 macOS 上执行；Claude Code 整理入库。

本文件记录 `dsh-recovery-resume` **0.1.3** 在真实 DSH 环境里的端到端验证结果。

## 验证通过的功能

在独立环境（独立 `DSH_HOME` + 独立端口 + 独立工作目录）里，用 0.1.3 实测通过：

| 功能 | 结果 |
|---|---|
| 识别被中断的回合 | ✅ 正确读出 `reason=interrupted`、回合序号，以及中断前最后一个工具名 |
| 投出续跑消息 | ✅ 消息真的进入会话事件流，`source.kind` 标记为 `dsh-recovery-resume` |
| 续跑后被中断的 agent 继续工作 | ✅ agent 收到消息后继续执行工具调用，完成了预期操作 |
| 冷却与计数落盘 | ✅ 写入 `$DSH_HOME/recovery-attempts.json`，含次数与回合序号 |
| 进程内去重 | ✅ 同一次服务运行内，同一会话只续跑一次 |

环境：DSH `0.1.6-alpha.1`，macOS。单元测试结果另见 README（85 项全过）。

## 未覆盖的部分

- **冷却上限（连续 3 次后停止）**：只触发了一次续跑，未验证超限后的行为。
- 验证用的「被中断的回合」是人工构造的。真实崩溃时，那条 `turn/end reason=interrupted`
  由 DSH 自身的崩溃修复逻辑在加载会话时补写；本次消费了它写出的结果形态，未复现写入过程本身。

## 复现环境的最小要求

需要满足两点，否则插件不会触发：

1. 会话**最后一条 `turn/end` 的 reason** 属于 `interrupted` / `error` / `max-tokens`；
2. 该条 `turn/end` **之后**没有新的 `turn/start`，也没有 `source.kind === "user"` 的消息。

第 2 条意味着：**不要拿正在被使用的会话来测试**——使用者随后发一句话，尾部就会出现用户消息，
插件会（正确地）拒绝续跑。请用独立环境。
